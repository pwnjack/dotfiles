# Conventions: full text

The long-form versions of the convention bullets in `CLAUDE.md`. `CLAUDE.md` keeps a short rule for each.

- `scripts/keybinds/keybinds-sheet.sh` is the one parse of `keybinds.lua`: `--json` feeds the Super+H overlay, `--markdown` feeds `docs/keybindings.md`, and `--print` is a terminal preview. Never hand-write rows. Each one-line `hl.bind(...)` has a trailing `--` label (`$vars` inside are resolved); `tst_Overlay` (run on every commit by `test/test-docs.sh`) fails if any real label is elided at 1366×768, 1920×1080, 2560×1440 or portrait 1080×1920, so shorten a label rather than shrinking the type. Media, mouse and wheel keys print their legend (`Volume Up`, `Left button`, `Wheel`); that display table is `_key_display`.
- `docs/keybindings.md` is **generated** by `scripts/docs/generate-keybindings.sh` from that same parser's `--markdown` mode — never hand-edit it, and regenerate after touching `keybinds.lua`. `test/test-docs.sh` fails on a stale copy, and since it lives in `test/` it runs on every commit. The skins differ in exactly one way: markdown does **not** resolve the options-backed `$terminal`/`$browser`, printing `options/terminal` instead, because a committed file must not freeze one machine's preference as though it were fixed. `scripts/lib/hypr-vars.sh` reads which variables those are from `apptype.lua`'s `read_option()` lines (`hypr_var_option`); never write that list by hand.
- `./test.sh` discovers suites rather than listing them: a tracked file is an entry point if it is named `run-tests.sh`, or matches `test-*.sh` and its directory has no `run-tests.sh`. Name a new suite either way and it is picked up — by the runner and by the pre-commit hook — with no registration step. A suite's *owning directory* is its own directory minus a trailing `test/` component, and that is what decides which commits run it; a top-level `test/` maps to the whole repo, which is why `test/test-runner.sh` runs on every commit. Each suite is run as `bash <path>` in its own process group and its exit code determines success, so a sourced-fragment harness and a standalone script coexist unchanged. The runner executes up to `TEST_JOBS` suites at once (default: `nproc`), including for `--for`; `TEST_JOBS=1` runs sequentially. Results and full failure output print in discovery order, with each suite's own elapsed time. A suite that cannot run a check because its dependency is absent prints a line starting `skip: <what> (<why>)` (leading spaces allowed) and carries on or exits 0; the runner prints those lines under the suite's result and counts them in the roll-up, and `TEST_STRICT=1` (set in CI) fails such a suite. Never report a skip as `pass`, and never gate a check on `command -v` without an `else` that prints `skip:`. A check deferred by the clock (a schedule boundary is now) prints `not run:`, so strict mode does not flake on it. Ctrl-C terminates active suite process groups and removes temporary output. Suites must use private fixtures for writable files, caches, runtime state and sockets, and stub commands that control the desktop. QML runners use temporary HOME and XDG directories; the overlay suite copies its QML/test layout so concurrent invocations do not share `real-sheet.json`, and the docs suite tests stale documents in a private tree. The hypridle parser suite points hypridle at a nonexistent private Wayland socket and D-Bus address: it registers the configuration before it tries to connect, so both listener checks run without touching the desktop, even outside a Wayland session.
- `scripts/hooks/pre-commit` decides nothing about which suites to run — it passes the staged paths to `test.sh --for`. It builds two staged listings on purpose: `--diff-filter=ACM` for shellcheck (a deleted file cannot be linted) and an unfiltered one for suite selection (a deletion is exactly when a suite most needs to run). Both use `--no-renames`, or git's single `R` record hides one of the two paths. `scripts/hooks/snapshot.sh` exports both listings and the staged contents from a copied index. All checks run in that temporary tree with private Git metadata and blobs (no commit history), never against unstaged working files or a shared writable object store.
- A control drawn from a `Rectangle` and a `MouseArea` says nothing to a screen reader, and a glyph says less. Every pointer area (`MouseArea`, `TapHandler`) in a `quickshell/<app>/*.qml` is therefore one of two things. A control: the item that owns the action carries `Accessible.role` (a button, a radio button or check box with `Accessible.checkable` and `.checked`, a list item with `.selected`, a slider, a link), `Accessible.name` (the visible label, bound to what the label shows; for a glyph-only control a short phrase saying what it does; a slider's name includes its value) and `Accessible.onPressAction` running what the click runs (a slider has `onIncreaseAction` and `onDecreaseAction`). Every such action starts with `if (enabled)`: Qt runs an accessible action on a disabled item, and an item's `enabled` reads false under a disabled ancestor too, so the one check covers a control that is off and a view that is fading out. A child `Text` that draws a glyph, or repeats what the control's name already says, is `Accessible.ignored`. Or not a control (it swallows clicks inside a card, closes on a click outside, only tracks hover): its opening line ends with `// a11y: not a control`. `quickshell/test-accessible.sh` counts per file: pointer areas against control roles plus markers on the areas' own lines, pressable roles against press actions, sliders against step actions, and actions that never mention `enabled`. It does not tie a role to its area, so a new control still needs its own name.

## Why the doctor and path rules exist

- `doctor.sh` and its check modules derive every target from tracked files. A hand-written list of paths, binaries or packages is a second source of truth and drifts, so a check parses the config that already declares them.
- Check modules never run their loops in a pipeline (`cmd | while read`): the severity counters are shell variables, and a pipeline runs the loop in a subshell, silently discarding every finding. Use `while read ...; do ... done < <(cmd)`. The test harness greps for this and fails the suite.
- Use `git ls-files -z` with `while IFS= read -r -d ''`, never plain `git ls-files`. Git C-quotes paths containing non-ASCII or quote characters, and the quoted form names no file on disk.
- `scripts/doctor/` and `docs/` are excluded from the doctor's literal-path scan, because both deliberately contain example paths that do not exist.
- `.gitignore` is a whitelist: `/*` ignores everything in `~/.config`, then one `!/<entry>` line per tracked top-level file or directory, then the runtime files inside those directories. A new app is therefore ignored with no edit, and tracking a new config means adding its `!` line. Never track what a program writes itself (app state, lock files, caches). Live copies of `defaults/` files go in the overlay block, anchored by their directory so no rule can hide the `defaults/` copy (see `state.md`).
