# User preferences (options/)

`options/` is this machine's rendered copy: the tracked defaults are in `defaults/options/` and the machine's differences are overrides in `~/.local/state/dotfiles` (see `state.md`). `echo firefox > options/browser` still sets one by hand; the next sync records it, and deleting a file resets it to its default. The untracked per-machine keys, with no default, are `calendar-*` (calendar names are personal), `capture-*` (the capture strip's; a missing file is the default) and `sound-*` (this machine's device names and hidden devices); they are kept as overrides, adopted on the first sync. Each reader is named in its component's doc, and the settings panel's `catalog.json` titles each row. `wallpaper` is a symlink to `~/.cache/current_wallpaper`, maintained by `wall.sh`.

One value per file, read at runtime. Shell scripts read them only through `option` in `scripts/lib/options.sh`: the first line with surrounding whitespace (a CRLF line's CR included) trimmed, or the caller's fallback when the file is missing, unreadable or that line is empty. Switches are on when the file says `enabled` and off otherwise, empty included; the capture strip's switches say `true` or `false`, and `bar-border` is the one switch that is on unless the file says `disabled` (`bar-modes.sh` and the panel read it the same way). The palette generator validates the three `theme-*` values: a missing or empty one uses the default quietly, and an invalid one warns and uses the default.

`mainmonitor` and `bar-output` are the value preferences that are legitimately empty: empty means "no preference" (for `bar-output`, every monitor), and every consumer resolves it itself. hyprlock draws on every monitor via `$monitor =` in `hardware/primary.conf` (a tracked symlink to `~/.local/state/hypr/primary.conf`, rendered from `options/mainmonitor`); `wall.sh` and the carousel state (through `scripts/lib/wallpaper.sh`) fall back to whichever monitor awww reports first, `restore-wallpaper.sh` (after Waypaper's saved choice) to the newest awww cache entry of any monitor, the SDDM watcher then takes any monitor's cache write as a change, the root SDDM helper `update_sddm_root.sh` keeps its own copy and takes the newest awww cache entry, and the desktop clock falls back to monitor 0. Nothing guesses a connector name: a tracked default such as `DP-1` or `eDP-1` is wrong on the next machine, which `scripts/doctor/checks/hardware.sh` guards. `hypr/config/hardware/monitor.lua` is host-neutral for the same reason; per-machine rules live in the untracked `~/.local/state/hypr/monitors.lua`, written by the settings panel's Displays page and loaded if present.
